# 目录说明：每个文件夹是干什么的

> 想知道「这个东西该放哪」「改了哪儿要跟着改哪儿」，看这份。
> 想知道「怎么加一个新源」，看 `新增渠道规范.md`。

---

## 一句话结构

```
00_路由      来源清单（手写，没有代码在读它）
01_采集      去外面抓回来
02_储存      原始数据，只进不改
03_加工      洗干净、转成表、下载图片
04_产出      给人看的东西
05_技能      规矩：怎么搭、怎么改、怎么查
.workbuddy   AI 的执行手册 + 私人工作记录（不在上面六层里）
```

**数据只往一个方向走**：

`01_采集 → 02_储存 → 03_加工 → 04_产出`

**不回头改原始数据。** 加工写错了，重新跑一遍加工；不改 `02_储存` 里的东西。

---

## 01_采集 · 去外面抓回来

一个源一个文件夹。**每个都自包含**——拷走能独立跑，删掉就干净消失。

| 文件夹 | 里面有什么 |
|---|---|
| `01_lingzao/` | 灵造（小红书博主 + 关键词搜索） |
| `02_getnote/` | 得到大脑（订阅博主的逐字稿 + 封面） |
| `README.md` | 跨源的说明：两个通道差在哪、凭证放哪 |

每个源文件夹里固定四个文件：

| 文件 | 干什么 | 进 git 吗 |
|---|---|---|
| `collect.py` | **唯一入口**。动作写在文件末尾的 `ACTIONS` 表里 | 是 |
| `config.json` | 配置。**真值字段留空**，只放结构和说明 | 是 |
| `config.local.json` | 配置真值。**现在只剩空壳** —— 真值已搬到项目根 `.env` | − 否，已 gitignore |
| `README.md` | 这个源能抓什么、怎么配、边界在哪 | 是 |

⚠️ **凭证放项目根的 `.env`，不放上面这两层里**（2026-09-21 起）：

- 那里不进 git，**也不会被拖进打包**
- 照 `.env.example` 复制一份再填
- 三层优先级：`config.json`（空） < `config.local.json`（空壳） < **`.env`（说了算）**
- 缺凭证时 `collect.py doctor` 会直接告诉你打开哪个文件

`doctor` 是自检入口：一条命令说清工具在不在、通不通、配置填对没有。

## 02_储存 · 原始数据

**从源头下来的东西，原封不动躺这儿。** 不放任何加工品——逐字稿、封面、表格都不属于这层。

按源分文件夹，按动作再分一层：

```
02_储存/
├── 01_lingzao/
│   ├── analyze-user-profile/    博主主页全量（含字幕合集 + artifacts 记录）
│   └── search-notes/            关键词搜索的结果
└── 02_getnote/
    ├── blogger/                 博主链路：博主列表 / 内容列表 / 逐条详情
    ├── link/                    链接笔记（save 存进来的）
    └── notes/                   早期动作留下的，已停用
```

**落盘文件名有讲究，改之前先看加工层靠什么认** —— 详细规矩见 `新增渠道规范.md` 第 5 节。

这层和 `04_产出` **都不进 git**——数据体积大，也不该公开。换机器要手动拷。

## 03_加工 · 代码层

**一个源一个文件夹，代码分开写、允许重复。**

```
03_加工/
├── 01_lingzao/         灵造那一套
├── 02_getnote/         得到大脑那一套
└── columns.md          列名词表（两边共同遵守的约定，不是代码）
```

每个源文件夹里，按职责拆成小文件：

| 文件 | 干什么 |
|---|---|
| `run.py` | 命令行入口，只做分派 |
| `adapter.py` | 源站的原始 JSON → 统一字段 |
| `record.py` | 统一字段长什么样 + 导出 csv/jsonl |
| `export.py` | 出 xlsx（版式、列宽） |
| `bundle.py` | 一条内容一个文件夹 + 封面归位 + 索引表 |
| `cover.py` | 封面下载（**这个源自己的规则**） |
| `video.py` | 视频下载（现在还是占位，拿不到直链） |
| `util.py` | 纯工具：时间转换、取标签、路径展开 |
| `table.py` | **只有灵造有**：读老的成品表 xlsx（历史数据没留 JSON 时的入口） |
| `scripts/` | **只有灵造有**：5 个被取代的旧脚本，留着备查，别照它写代码 |

**`03_加工/` 下只有那两个文件夹 + `columns.md`。** 你之前看到的 `adapters/` 已经删了。

⚠️ 文件夹名以数字开头 → **不是合法 Python 包名** → 层内只能用同目录扁平导入
（`from record import ...`），别写 `from .record import`。

## 04_产出 · 给人看的

```
04_产出/
├── 博主/<昵称>_<账号ID>/
│   ├── _索引.xlsx               统一字段 30 列
│   ├── _逐字稿合集.md            只有灵造有
│   └── <发布日期>_<标题>/        一条内容一个文件夹
│       ├── 逐字稿.md             信息头 + 正文 + 逐字稿（一个文件看全貌）
│       └── 封面.jpg / .webp      有才放
├── 图片/<昵称>_<账号ID>/         封面池（缓存，不是给人读的）
├── 表格/                        成品表
├── 文件/  视频/                 空着，预留
└── README.md                    产出库说明
```

**单条目录里固定只有两样东西**：`逐字稿.md` 和 `封面.*`。
（`笔记信息.md` 已经废了，内容合并进 `逐字稿.md`——2026-09-19 定的。）

命名规矩、字段含义、"未知"和 0 的区别，都在 `04_产出/README.md`。

## 05_技能 · 规矩层

**不放业务代码**（`selfcheck.py` 是唯一的例外——它是执行规矩的）。

| 文件 | 什么时候看 |
|---|---|
| `prereq_check.py` | **第一次用 / 换了电脑先跑**。查 Python 依赖、灵造、得到大脑各装了没、配了没；缺什么打印怎么装、装哪 |
| `打包排除清单.md` | **打包发人前对一遍**。钥匙、数据、私人记录都不能进包 |
| `selfcheck.py` | **动手前跑一下**。八项自检，把静默问题摆出来 |
| `目录说明.md` | 就是这份 |
| `新增渠道规范.md` | 要加第 3、第 4 个源 |
| `新源测试流程.md` | 新平台接进来，怎么测、测到什么程度算能用 |
| `开发复盘.md` | 想知道「为什么是这个结构」 |
| `灵造使用说明.md` | 查灵造的参数 / 积分 / 脚本路径（官方手册快照） |

## 00_路由 · 来源清单

`routes.json`——**手写的备查清单，全项目零代码引用**。

留着是因为它把「有哪些源、各自花钱吗、落哪、边界在哪」记在一处，适合人翻。
**但别以为它现在在生效**——改代码不会影响它，改它也不会影响代码。

## .workbuddy · 不在流水线上

```
.workbuddy/
├── skills/project-crawl-pipeline/SKILL.md    AI 的执行手册（引擎自动加载）
└── memory/                                    AI 的工作记录
    ├── MEMORY.md                             项目约定与铁律（每次会话自动注入）
    └── YYYY-MM-DD.md                         当天做了什么
```

**这一层不是「项目的文件夹」，是引擎和 AI 之间的接口**——性质跟 `.git/` 一样。

- **代码不依赖它**。删掉整个 `.workbuddy/`，4260 行 Python 照常跑，只是下次 AI 接手会重新踩一遍坑。
- `skills/` 进 git（两边都跟着项目走）；**`memory/` 不进 git**——里面有私人笔记 ID、邮箱、积分余额，不公开。

## 改动之后，这几处要跟着改

项目最容易过期的不是代码，是文档——散在九个地方。**改完顺手扫一遍。**

| 你改了什么 | 要跟着改哪儿 |
|---|---|
| **加了一个源** | `05_技能/新增渠道规范.md` 的验收清单逐条打勾、根 `README.md`、`使用说明.md` |
| **命令路径** | 根 `README.md`、`01_采集/README.md`、各源 `README.md`、`04_产出/README.md`、`使用说明.md` |
| **凭证位置 / 环境文件** | 根 `README.md`、`使用说明.md`、`01_采集/README.md`、各源 `README.md`、本文件、`新增渠道规范.md`、`打包排除清单.md`、`02_getnote/collect.py` 的 doctor 提示语 |
| **价目 / 花费** | 灵造 `README.md`、**`01_采集/01_lingzao/collect.py` 的 `cost` 字段**、根 `README.md` |
| **产出结构** | `04_产出/README.md`、本文件、`03_加工/columns.md` |
| **列名** | `03_加工/columns.md` + 两个 `record.py`（而且**老表要重跑**） |
| **能力边界** | `01_采集/02_getnote/README.md`、`.workbuddy/memory/MEMORY.md`、SKILL.md |
| **落盘命名** | 加工层的 glob + 正则两处都要过、本文件 |
| **打包规则** | `05_技能/打包排除清单.md`、`.gitignore` |

⚠️ **`collect.py` 的 `cost` 字段比文档更危险**——它直接印在预跑输出上，你控预算就盯那一行。

**一条判断标准**：文档里提到旧名字时，是在「引用它」还是在「说明它已经废了」？
后者不用改——否则会把历史记录和兼容代码一起改烂。

## 现在的成熟度：内部使用阶段

| 通 | 状态 |
|---|---|
| 得到大脑（博主订阅 → 逐字稿 + 封面 → 出表） | **稳定**，端到端跑通 |
| 灵造（博主主页 → 字幕全文 + 封面 → 归档） | **基本可用，偶尔不稳** |
| 加工层（两个源都） | **稳**——纯本地，不联网、不看第三方脸色 |

**所以有几件事先说清，别当成成品：**

- **采集层的稳定性取决于外部服务**。第三方限流、改接口、链接过期，都能让它当场失灵。
- **灵造那边还差点意思**：封面链接 3 小时就过期（晚了补不回来）、字幕偶尔转写失败。
- **不要对外当"成品"宣传**。要试新平台，先照 `新源测试流程.md` 走一遍，看实测效果再决定留不留。
- **产出数据仅供内部参考**——字段缺失（比如得到大脑没有互动数据）是源头如此，不是抓漏了。
