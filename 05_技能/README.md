# 05_技能 · 这一层放什么

**这一层不装业务代码，装「规矩」——外加一个执行规矩的脚本。**

前四层是流水线（采集 → 储存 → 加工 → 产出），这一层讲**流水线本身该怎么搭、怎么改**。
代码会变，规矩变得慢，所以单独放一层。

---

## 里面有什么

| 文件 | 干什么 / 什么时候用 |
|---|---|
| **`selfcheck.py`** | **动手前先跑它。** 八项自检：密钥 / 落盘命名 / 逐字稿截断 / 封面覆盖 / 条数对账 / 四层结构 / 配置残留 / 表里「未知」 |
| **`目录说明.md`** | 每个文件夹是干什么的、**改完哪儿要跟着改**、现在的成熟度。迷路时先看这份 |
| **`新增渠道规范.md`** | **要加第 3、第 4 个源的时候**。九步总览、骨架、模板、采集层六个必须有、加工层八个文件职责、验收清单 |
| **`新源测试流程.md`** | **试新平台的时候**。测哪五件事、四级测试（L0–L3）、判定「能用／勉强／别用」、测试记录表 |
| `开发复盘.md` | 想知道「为什么是这个结构」的时候。踩过的三十处坑、做错的决定、还欠的账 |
| `灵造使用说明.md` | 灵造官方手册快照。查参数、积分、脚本路径 |

**加一个新源，按这个顺序读**：

```
① 新源测试流程.md    → 这平台值不值得接（不值就别搭）
② 新增渠道规范.md    → 九步，搭起来
③ 目录说明.md        → 收尾：哪几处文档要跟着改
```

```bash
python 05_技能/selfcheck.py            # 全量
python 05_技能/selfcheck.py --quiet    # 只看「错误」和「警告」
```

首次 clone 下来还没有数据时，它不会崩——只会提示「还没抓过数据」。

## 为什么有的东西是脚本、有的是文字

**能查的做成脚本，该判断的写成文字。**

- 脚本给的答案**确定**——跑一次就是一次，不用赌 AI 记没记住几十条清单。
  这个项目最危险的 bug 全是「不报错但是错的」（文件名少个下划线、字幕撞截断上限、
  20 条被读成 40 条），正适合脚本盯着。
- 文字留给**判断标准和「为什么」**——这些脚本给不出，得看着现象自己推。

所以技能里那一大段「纠错清单」被砍掉一半：**可执行的部分搬进了 `selfcheck.py`**。

## 和 `.workbuddy/skills/` 什么关系

两处都有「技能」字样，分工不同：

```
.workbuddy/skills/project-crawl-pipeline/SKILL.md   ← AI 的执行手册（引擎自动加载）
05_技能/                                            ← 项目规范资产 + 自检脚本（人读 / AI 按需读）
```

- **SKILL.md** 讲「**哪里会出错**」——密度高、AI 每次动手前就该知道
- **这一层** 讲「**按什么顺序搭**」+「**现在有没有问题**」（跑脚本）

`.workbuddy/` **不在 `.gitignore` 里**，两边都进 git、都跟着项目走。
（只有 `.workbuddy/memory/` 被排除 —— 那里有私人笔记 ID / 邮箱 / 余额，不公开。）
