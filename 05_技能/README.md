# 05_技能 · 这一层放什么

**这一层不装代码，装「规矩」。**

前四层是流水线（采集 → 储存 → 加工 → 产出），这一层是**流水线本身该怎么搭、怎么改**的规范。
代码会变，规矩变得慢——所以单独放一层。

---

## 里面有什么

| 文件 | 什么时候读 |
|---|---|
| **`新增渠道规范.md`** | **要加第 3、第 4 个源的时候**。骨架、采集层六个必须有、加工层八个文件职责、验收清单 |
| `开发复盘.md` | 想知道「为什么是这个结构」的时候。踩过的三十处坑、做错的决定、还欠的账 |
| `灵造使用说明.md` | 灵造官方手册快照。查灵造的参数、积分、脚本路径 |

---

## 和 `.workbuddy/skills/` 什么关系

两处都有「技能」字样，但分工不同：

```
.workbuddy/skills/project-crawl-pipeline/SKILL.md   ← AI 的执行手册（引擎会自动加载）
05_技能/                                            ← 项目规范资产（人读，AI 按需读）
```

- **SKILL.md** 讲「**哪里会出错**」——实测纠错清单，密度高、要 AI 每次动手前就知道。
- **这一层** 讲「**按什么顺序搭**」——规范、复盘、手册。AI 接到「加新源」这类任务时，
  先读 `新增渠道规范.md` 再动手。

`.workbuddy/` **不在 `.gitignore` 里**，所以两边都进 git，都跟着项目走。

---

## 为什么不做成一个文件

因为读的人不同、读的时机不同：

- 加新源 → 读规范（一份，完整走一遍）
- 排查怪现象 → 读 SKILL.md 纠错清单（按现象查）
- 想推翻某个设计 → 读复盘（那里写了当初为什么这么定）

**混在一起会两头不讨好**：规范被纠错清单打断，纠错清单被规范淹没。
