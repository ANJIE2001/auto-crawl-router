# 打包排除清单

> 要把这个项目**发给别人**（压缩包 / 拷 U 盘 / 上云盘）之前，照这份对一遍。
> 只给自己换电脑的话，看最后一节。

---

## 一句话

**钥匙本来就不在项目里。** 凭证存在**你自己电脑**的环境变量 / 注册表里
（用 `python 05_技能/set_key.py` 设，用法见那份文件的说明）—— 包发出去，里面没有 key。

**能发的是「代码 + 文档」，不能发的是「数据 + 私人记录」。**

| 类别 | 具体 | 为什么不能发 |
|---|---|---|
| 📦 **数据** | `02_储存/` | 抓回来的原始数据，体积大 |
| 📦 **数据** | `04_产出/` | 成品和封面，体积大 |
| 🔒 **私人记录** | `.workbuddy/memory/` | 私人笔记 ID、邮箱、积分余额 |
| ⚠️ **兜底排除** | `.env` | 平时是空模板。**万一你临时往里填过真值**，排掉才不漏 |
| ⚠️ **兜底排除** | `01_采集/*/config.local.json` | 老位置，现在也是空壳。保险起见一律排除 |
| 🗑️ **垃圾** | `.git/`、`__pycache__/`、`*.pyc`、`.tmp_*` | 没用，白占体积 |

> **为什么还留那两条「兜底排除」**：项目里本来不该有 key，但人总有手快的时候。
> 排除清单是最后一道闸 —— **不靠记性，靠规则**。

## 怎么执行

### 打个压缩包发给别人（PowerShell）

```powershell
# 在项目根目录跑
$out = "..\自动抓取内容路由_分发版.zip"
$skip = @(".env", ".git", "02_储存", "04_产出", "__pycache__", "config.local.json")
Get-ChildItem -Recurse -File | Where-Object {
    $rel = $_.FullName.Substring((Get-Location).Path.Length + 1)
    -not ($skip | Where-Object { $rel -like "*$_*" })
} | Compress-Archive -DestinationPath $out -Force
```

### 发之前自检

```bash
# 1. 项目里有没有混进密钥（八项自检的第一项就是它）
python 05_技能/selfcheck.py --quiet

# 2. 看凭证存在哪 —— 应该显示「用户环境变量」或「注册表」，不该显示「项目根 .env」
python 05_技能/set_key.py

# 3. 解压到临时目录，翻一遍有没有 .env / config.local.json
```

**第 2 步要是显示「项目根 .env ⚠️ 建议搬进环境变量」，先按提示搬走，再打包。**

## 关于「专家包」

如果你说的是**发给学员的专家包**（`niki-clone.zip` 那种，装进 WorkBuddy 的）：

那个包里**本来就没有这个项目文件夹** —— 它是专家人格 + skills，不带数据也不带凭证。
所以得到大脑的 key 不会进去。**但仍然不能让 key 出现在任何你手动打包的东西里。**

两种包都按上面这份清单排 —— 排除规则写死，不靠记性。

---

## 别人拿到包之后要做什么

1. **装前提软件**：`python 05_技能/prereq_check.py` —— 它会说明缺什么、怎么装、装哪
2. **配他们自己的 key**（不是你那把）：
   ```bash
   python 05_技能/set_key.py getnote --client-id cli_xxx --api-key gk_live_xxx
   ```
3. 再跑一次 `prereq_check.py`，三样「就绪」就能开跑

## 只给自己换电脑

那就不用排得这么狠，但有个关键区别：

- 直接整个文件夹拷过去（含 `02_储存` / `04_产出`，省得重抓）
- **凭证不用拷，也拷不走** —— 它在系统里，不在文件夹里。**在新电脑上重新设一次**：
  ```bash
  python 05_技能/set_key.py getnote --client-id cli_xxx --api-key gk_live_xxx
  ```
- `~/.lingzao/`（灵造 CLI 本体和凭证）**也在项目外面**，单独拷或者重新装
  - 装完记得补那个 Windows 启动器 `lingzao.cmd`，不然项目找不到它（做法见 `prereq_check.py` 的输出）
- 全套检查：`python 05_技能/prereq_check.py`

---

## 为什么不能只靠 `.gitignore`

`.gitignore` 只管 **git 仓库**，管不了你手动拖进压缩包的文件 ——
**这是一份补那个缺口的清单。**

`.env` 已经写进 `.gitignore` 了（不会被误提交），但那和「打包时会不会被带走」是两回事。
