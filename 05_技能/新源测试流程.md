# 新源测试流程

> 试一个新平台，走这一遍。
> 目的不是「跑通了没」，是**「这个源值不值得接、产出的东西能不能用」**。
>
> 每试一个平台，留一张记录（见文末表格），以后能横着比。

---

## 一、先测五件事，别急着写代码

拿到一个新 API，先把这五条问出来。**用最土的办法**——curl、Postman、
或者随手写几行脚本都行，**这时候不写正式代码**。

| # | 问什么 | 怎么看 | 为什么关键 |
|---|---|---|---|
| 1 | **拿得到吗** | 一条请求通不通、要什么授权 | 通不了就别往下走了 |
| 2 | **给的是"内容"还是"数据"** | 返回里有正文/逐字稿吗？有互动数吗？ | 只给内容的源，指标列全是「未知」——**别填 0** |
| 3 | **全不全** | 抽 20 条，数一数：有正文几条、有图几条、有稿几条 | 覆盖率决定它能不能当主力源 |
| 4 | **字段比文档多还是少** | 把真实响应 dump 出来，数键的个数 | 实测常比文档多（得到大脑详情：文档 6 个、实测 12 个） |
| 5 | **什么脾气** | 链接有签名吗？会限流吗？重跑会重复吗？ | 决定采集和加工怎么写 |

**第 5 条最容易吃亏**——两个源的封面看着都是封面，一个 3 小时过期要抢、一个永久有效随时补。
**先实测清楚，别照抄隔壁源的写法。**

---

## 二、四级测试：逐级加压

**别一上来全量抓。** 每级都要过，过不了就停下修。

### L0 · 连通
**动作**：发一条最轻的读请求。
**过关**：HTTP 200，返回结构能看懂。
**不过关**：查授权头写法、Base URL 有没有多余/缺少的路径段。

> 实测坑：得到大脑的 Base URL 两份官方文档写法不一致（带不带 `/open`），
> 以实测为准。

### L1 · 冒烟（3 条）
**动作**：拉 3 条，把**完整响应 dump 成文件**。
**过关**：能数出字段清单；能找到「正文 / 标题 / 时间 / 唯一 ID」这四样。
**重点**：
- **唯一 ID 是哪个字段？** 身份全靠它，后面所有匹配都认它，不认标题
- **正文是一份还是多份？** 得到大脑的链接笔记有**两个正文**（网页原文 / AI 解读），入库前要先定用哪个

### L2 · 小样本全链路（20 条）
**动作**：拉 20 条 → 落盘 → 加工 → 出表。
**过关**：
- 20 条全落盘，失败 0
- `04_产出/` 里**看得见东西**（表 + 逐字稿 + 封面）
- 表里列名和 `03_加工/columns.md` 对得上
- 没有数据的列显示「未知」，不是 0

**这一级是分水岭。** 过不了 L2，说明适配器或命名有问题。

### L3 · 稳定性（连跑两次）
**动作**：同样的命令**再跑一次**。
**过关**：
- 条数不变（不翻倍、不少）
- 不堆 `_2` 之类的重复文件
- 产出目录是「复用旧的」而不是「又新建一批」
- 中间没被限流打断（被打断了看要不要加间隔）

**这一级专抓静默错误**——实测踩过：文件名带日期，跨天并存，20 条被读成 40 条。
不报错、exit code 0、数字是错的。

## 三、判定：什么样的源算「能用」

过完四级，按这张表下结论：

| 看什么 | 能用 | 勉强 | 别用 |
|---|---|---|---|
| **正文/逐字稿覆盖率** | ≥ 90% | 70–90% | < 70% |
| **唯一 ID** | 有稳定 ID | 有但会变 | 没有（只能靠标题匹配，会串行） |
| **封面** | 拿得到，且不过期 | 拿得到但会过期 | 拿不到 |
| **重跑** | 幂等 | 手动清理也行 | 每次堆重复 |
| **字段** | 能填满身份+标题+时间+正文 | 缺一两样 | 连正文都没有 |

**低于「能用」的源也可以接**——但要在它自己的 `README.md` 里写明**缺什么、为什么缺**，
别让以后看表的人误以为是抓漏了。

## 五、新平台常踩的坑

| 坑 | 现象 | 怎么防 |
|---|---|---|
| **文档字段表不全** | 按文档写适配器，漏数据 | L1 先把真实响应 dump 出来看 |
| **文档枚举不全** | 拿枚举当白名单校验，报错 | 见过文档里没有的取值（`class_audio`），别当白名单 |
| **Base URL 不一致** | 两份文档写法不同 | 实测一个请求定下来，写进 README |
| **大整数精度丢失** | ID 变成科学计数法 | ID / 游标一律当**字符串**处理 |
| **异步接口** | 返回 task_id，要轮询 | 先确认是同步还是异步再写代码 |
| **桶级限流** | 连着调两个接口就 429 | 每条之间留间隔（得到大脑实测 3.5 秒） |
| **链接带签名会过期** | 隔天去下图，全 498 | 采集时当场下；判清有效期 |
| **重名不加序号** | 抓两次，第二次覆盖了第一次 | 想清楚用覆盖还是留历史（见规范第 2 节⑥） |
| **标题被改写** | 入库标题和原帖不一样 | **标题一个字都不许改**（铁律），自己传 |

## 六、测完之后的去向

| 结果 | 怎么办 |
|---|---|
| **能用** | 照 `新增渠道规范.md` 搭采集层 + 加工层，验收清单逐条打勾 |
| **勉强** | 同上，但在该源 `README.md` 里写明缺什么、边界在哪 |
| **别用** | **什么都不用建**。把记录表留下就行——以后别人（或你自己）想试同一个平台时能省一遍 |
