# 回填规范：把本地逐字稿写回飞书表

> 想知道「回填是什么、为什么这么做」，看这份。
> 想知道「怎么加一个新源」，看 `新增渠道规范.md`。

---

## 一句话

本地 `_索引.xlsx` 里的逐字稿 → **按笔记ID** → 飞书「笔记」表的三列。

```
04_产出/博主/<昵称>_<账号ID>/_索引.xlsx
        │  取「笔记ID」+「逐字稿」
        ↓
   03_加工/回填/fill_feishu.py      ← 预演 → 你点头 → 再写
        ↓
飞书多维表格「笔记」表
   逐字稿 / 逐字稿来源 / 逐字稿状态
```

---

## 为什么写表不用 RPA

RPA 是模拟点击：界面一改版就挂，挂了还看不出错在哪儿。

写表是**确定性动作** —— 哪个记录、哪个字段、写什么，全都明确。走开放接口能做到：
200 条一批、有返回码、失败能定位、重跑幂等。

所以分工是：

| 动作 | 用什么 | 为什么 |
|---|---|---|
| **抓**（博主主页、笔记详情） | RPA / 灵造 | 抓没有官方接口，只能模拟 |
| **写**（回填飞书） | **飞书开放接口** | 有接口就别模拟 |

**别让 RPA 去干写表的活**，那是拿最脆的工具做最该稳的事。

---

## 三条铁律

### ① 只按笔记ID匹配，绝不按标题

同一个博主会有**同名笔记**（实测 nana 账号里两条都叫「Codex 一键智能剪辑 Skill 开源了！」，
08-08 和 08-12 各一条）。按标题匹配必然串行，而且串了还不报错。

---

### ② 只更新，不新建

表里没有的笔记ID，只报告数量，**不追加记录**。

理由：本地库是「我抓过的」，飞书表是「我要给人看的」，两者本来就不该一样。
自动新建会把你的表塞进一堆你没打算展示的东西，而且很难清。

---

### ③ 本地没稿时，默认不碰单元格

空值默认跳过，不会把你在飞书里手填的内容冲掉。

真要清空加 `--clear-empty`。**默认永远是保守的那个。**

---

## ★ 标准做法（定为规范，别再临时想）

> **凡是飞书表里的笔记链接，逐字稿一律交给得到大脑抓。**

理由：链接给过去它就能抓，**0 元**，不用装模型、不用买积分、不用管视频下没下下来。
原文里也已经把视频口播拼好了（`web_page.content`），一步到位。

**只有这三种情况才换别的路**：

| 情况 | 换什么 |
|---|---|
| 链接失效 / 页面要登录，得到大脑抓不到 | 本地转写（要吃 mp4） |
| 只要口播、不要文案，且原帖没挂字幕 | 灵造文案提取（0.3 元/条） |
| 已经在灵造那边抓好、表里只是要同步 | `fill_feishu.py` 搬运，不重新抓 |

除此以外，**默认走得到大脑，不要每次重新论证一遍**。

### 一条要多久

实测 14 条：**平均 25 秒/条，区间 15～50 秒**。

慢在三处：提交排队、下载页面、转写视频。**视频越长越慢**，1 分钟的短视频 20 秒左右，
十几分钟的长视频会顶到 50 秒往上。

| 一次跑多少 | 预计耗时 |
|---|---|
| 10 条 | 约 4 分钟 |
| 50 条 | 约 20 分钟 |
| 100 条 | 约 40 分钟 |
| 300 条 | **约 2 小时** |

**所以超过 50 条就分批跑**，不要一口气怼 300 条：

```bash
python 03_加工/回填/pull_getnote.py --limit 50 --go    # 第一批
python 03_加工/回填/pull_getnote.py --limit 50 --go    # 第二批（自动接着上次）
```

状态列就是进度文件，**随时中断、随时重跑，已标「有稿」的不会再抓**。
跑的时候不用守着，但要保证电脑不睡眠 —— 这是本地脚本在发请求，不是云端任务。

### 成本

**0 元**。得到大脑是会员制，只占接口次数，不扣钱、不扣积分。
唯一要留意的是接口次数上限（read 日 20000），300 条远够用。

## 表里的三列

| 列名 | 类型 | 谁写 | 说明 |
|---|---|---|---|
| `逐字稿` | 文本 | 脚本 | **链接原文全文**（含视频口播），来自得到大脑 `web_page.content` |
| `逐字稿来源` | 单选 | 脚本 | `灵造` / `得到大脑` / `本地转写` |
| `逐字稿状态` | 单选 | 脚本 | `有稿` / `无稿` / `失败` |

⚠️ **「逐字稿」= 链接原文，不是 AI 解读。** 这两个别混：

| 字段 | 是什么 | 要不要 |
|---|---|---|
| `web_page.content` | **链接原文**（博主写的 + 视频口播，口播段满是「消掉」「销掉」这种同音错字） | ✅ **要这个** |
| `content` | AI 解读版（重写、带表格、丢细节） | ❌ 不要 |

原文里唯一要去掉的是 `![](图片)` 那种 markdown —— 渲染用的，回填没意义。
**别只取「看起来像口播」的那一段**，会把博主写的文案扔掉。

**为什么不全塞进「笔记内容」**：那一列在两类笔记里含义不同 —— 图文笔记它是正文，
视频笔记它只有文案加话题标签。逐字稿是完整原文，混在一起以后分不出哪条是全文。

## 两个脚本，方向正好相反

| 脚本 | 数据从哪来 | 干什么 | 何时用 |
|---|---|---|---|
| `fill_feishu.py` | 本地 `_索引.xlsx`（已抓好、加工过） | **搬**到飞书 | 本地有货，想让飞书表也有 |
| `pull_getnote.py` | **飞书表里的笔记链接** | 去得到大脑**抓**原文，回填飞书 | 飞书表里只有链接、没有内容 |

**别搞混**：前者不发网络请求（纯搬运，秒级），后者每条要 15～30 秒。

## 抓取式回填：飞书链接 → 得到大脑 → 飞书

```bash
# 预演：只列待处理的，一条都不抓
python 03_加工/回填/pull_getnote.py

# 先跑 4 条看质量（约 1.5 分钟）
python 03_加工/回填/pull_getnote.py --limit 4 --go

# 全部跑（已标「有稿」的自动跳过）
python 03_加工/回填/pull_getnote.py --go

# 连有稿的也重抓
python 03_加工/回填/pull_getnote.py --redo --go
```

链路是三步，实测 15～30 秒一条：

```
POST /resource/note/save              → 普通链接是异步，返回 task_id
POST /resource/note/task/progress     → 轮询到 success，拿 note_id
GET  /resource/note/detail?id=        → web_page.content = 链接原文
```

**三条必须守住的**：

1. **标题必须传**。不传 `title`，得到大脑会用 AI 重写标题（原帖「恐惧很深的人…」
   → 「深度认知：恐惧深厚个体的人生成长路径解析」），回来就对不上了。
2. **状态列就是进度文件**。已标「有稿」的下次跳过；中断了直接重跑，不会重复抓。
3. **每抓完一条立刻写回**，不攒到最后 —— 一条 30 秒，攒着中断就全丢。

原始 JSON 会落到 `02_储存/02_getnote/link/<日期>_note_<note_id>.json`，回溯用。

⚠️ **成本**：0 元（会员制），但占接口次数。14 条约 5 分钟。

## 搬运式回填：本地 → 飞书

```bash
# 1. 预演（默认，飞书一个字都不动）
python 03_加工/回填/fill_feishu.py

# 2. 看清楚「能匹配上几条」再决定
python 03_加工/回填/fill_feishu.py --go

# 指定别的数据源
python 03_加工/回填/fill_feishu.py "04_产出/博主/nana娜娜呀_xxx/_索引.xlsx" --go
```

预演会告诉你四件事：本地多少条、多少条有稿、能匹配上几条、多少条表里没有。
**「能匹配上 0 条」是好消息不是坏消息** —— 说明两边不是同一批，没写错表。

写之前会把要写的内容快照到 `_fill_tmp/backup_<时间>.json`，写坏了能照着还原。

## 踩过的坑

**① select 字段必须传数组，不是字符串**

```json
"逐字稿状态": ["有稿"]      ✅
"逐字稿状态": "有稿"        ❌ 静默失败或报类型错
```

**② 拉记录的 output 文件会留 manifest**

lark-cli 写 ndjson 时会同时生成 `xxx.manifest.json`，下次同名输出直接报
`output file already exists`。脚本里已经先删再加 `--overwrite`，**改这段别改回去**。

**③ 表头不在第 0 行**

`_索引.xlsx` 的布局是：第 0 行标题、第 1 行空、第 2 行才是表头。
所以脚本**找第一个含「笔记ID」的行**当表头，别硬编码行号 —— 改了版式也不会瞎。

**④ 逐字稿有全文和截断两种**

灵造 JSON 里的 `subtitle.plain_text` 是截断版（实测卡 1203 字），
`_索引.xlsx` 里的是**全文**（实测最长 3547 字）。所以回填读 xlsx，别去读原始 JSON。

📏 判断法：各条长度一样 = 截断；长度各异 = 全文。

**⑤ 30 列里「未知」不是 0**

回填不涉及数值列，但如果以后要回填互动数据，记住：「未知」是「这个来源没这个字段」，
不是「确实是 0」。混在一起会让人误判。
