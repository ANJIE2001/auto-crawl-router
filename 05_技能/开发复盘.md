## 一、踩了多少坑

记录在案的三十处上下。**能写下来的都是踩过的** —— 没踩的不会想到去记。

真正的坑不在技术上难，而在**它们都是静默的**：不报错、exit code 还是 0，只是结果是错的。

### A. 这台机器的脾气（5 处）

| 坑 | 后果 |
|---|---|
| Bash 工具缺 coreutils（`head`/`ls`/`cat`/`grep`/`sed`/`dirname` 全没有） | 管道基本废，所有逻辑得写成文件再跑 |
| PowerShell 工具 stdout 不回传 | 打不出结果 |
| `.cmd` 参数里的 `&` 被 cmd.exe 切成命令分隔符 | 小红书分享链接必然踩，报「'xsec_source' 不是内部或外部命令」 |
| **反引号塞进 bash 双引号 → 被当命令替换吃掉** | **写进文件的内容静悄悄缺一大块，exit code 还是 0** |
| `reg.exe` 被程序黑名单拦住 | 读不了注册表，只能换路子找环境变量 |

**防法**：逻辑写成 `.js`/`.py` 落文件再跑；结果写文件、用 Read 读。含反引号的内容一律用 Write 落盘。

### B. 数据源的脾气（最多的一类）

**灵造**

- 三种命令的结果塞在同一个壳里（`{"ok":…, "data":{"type":"<命令名>", "items":[…]}}`）→ 按 `data.type` 分派
- 字幕是**截断的**（`truncated: true`），全文只在 artifact URL 里
- **封面 URL 只有约 3 小时寿命**。实测：40 条老数据去补 → 24 条 498 + 16 条 403，**一张没救回来**
- **两种命令的时长字段名不一样**：profile 用 `media.video_duration_seconds`（秒），search 用 `media.video.durationMs`（毫秒）。我第一版只认后者，统计出「0 条视频」——**不报错，静默算错**

**得到大脑**

- **429 桶级限流**：连调两个接口就撞，等 4 秒恢复
- **CLI 和 HTTP 的字段不一样**：CLI 不给 `post_cover`（封面只在 HTTP）；`save` 在 CLI 里是**同步**的，HTTP 里是异步要轮询
- **AI 会重写标题**。原帖「恐惧很深的人，乐在其中，会很有厚度」→ 变成「深度认知：恐惧深厚个体的人生成长路径解析」
- 详情返回的 `post_id_alias` 是**空串** → 身份只能从文件名取
- `post_url` 是 **483 字**的超长链接（带 `share_sign`/`ts`/`u_code`）
- `note_type` 实测出现文档里没列的 `class_audio` → **别拿文档枚举当白名单校验**
- 链接笔记有**两个正文**（`web_page.content` 原文 / `content` AI 解读），是两个不同字段

### C. 数据完整性（最危险的一类）

| 坑 | 为什么危险 |
|---|---|
| **同一个博主会有同名笔记**（nana 账号里两条都叫「Codex 一键智能剪辑 Skill 开源了」） | 按标题匹配必然串行 → **身份永远认笔记 ID，不认标题、不认序号** |
| 逐字稿缺失分三态：`failed`（能重抓救）/ `missing`+有时长（视频没人声，白花钱）/ `missing`+无时长（源信息拿不到） | 混在一起就分不清该不该重抓 |
| **「未知」和「0」是两回事** | 得到大脑没有互动数据，导出「未知」。写成 0 会让人误判成"互动惨淡" |
| **CRLF/LF 假差异**：`read_text`+`write_text` 复制文件，Windows 悄悄把 LF 转成 CRLF | 两份「内容一样」的文件字节数不同，**排查这种假差异会白费功夫**，甚至差点误删唯一副本 |

### D. 我自己的判断失误（最该记的）

**三次把"我的实现范围"说成"客观限制"**：

| 我说过 | 实际 |
|---|---|
| 「得到大脑的封面拿不到」 | **HTTP API 一直通着**，是我没走那条字段 |
| 「原帖标题没保留在任何字段里，改了就找不回来」 | 它在 `attachments[0].title`，**三条全验证都在** |
| 把两个源的数据并排写在一张表里 | 看着像一回事，其实两条链路、两个博主、互不相干 |

**还错两次在同一个地方**：拿标题的**长短**判断 `attachments[0].title` 是不是标题。
小红书的标题**本身就是正文第一句**（「零成本变美方案」那条），按长短判直接判反。

**最严重的一次**：写了个"找最新一条非 link 笔记"的脚本去挑目标 →
**挑中了私人手账笔记**。我用排除法猜他想看哪条，而他要看的是完全另一条。
→ 规矩改成「先列候选，不自动挑」。

**最贵的一次**：建这个项目的早期陷入调研循环 —— 40+ 次重复读同一批文档、零文件产出，
白烧约 12 元额度。用户原话：「**扣了这么多积分……我不想再看到这种情况出现**」。
→ 现在有条硬规矩：单次任务调研类调用 ≤15 次，到顶要么开写要么汇报。

### E. 工程类（3 处）

- **目录名以数字开头 → 不是合法 Python 包名 → 不能用相对导入**。这几层一律 `from record import ...`，靠 `sys.path.insert`，没有 `__init__.py`
- **重跑必须幂等**：按笔记 ID 认领已有目录，不然堆出 `xxx_2`
- **Excel 锁文件** `~$xxx.xlsx` 会让重跑报 `PermissionError` —— 不是代码问题

## 三、代码评审

### 立得住的六条

1. **删目录即卸载** —— `01_lingzao/` 和 `02_getnote/` 之间零引用。删一个，另一个毫发无伤。
   这不是口号：改灵造的 `record.py` **碰不到**得到大脑任何一个文件。
2. **列名统一、代码分开** —— 各自实现字段定义，但中文列名守同一套词（`columns.md`）。
   于是"能卸载"和"表能合并"同时成立，不用二选一。
3. **`raw` 整条保留** —— 统一字段之外，原始条目挂在 `raw` 上。清洗写错了能回溯。
4. **三态诚实** —— 「未知」≠ 0。数据源没有的字段不写 0 冒充。
5. **幂等重跑** —— 靠笔记 ID 认领，重复导出不会堆副本。所以可以放心重跑。
6. **付费源预演** —— 不加 `--go` 只打印命令、路径、花费就停。

### 可议的五条

1. **代码重复是真实成本**（两个 `collect.py`、两套 `record/export/adapter/bundle`）。
   你拍板可接受，换来卸载干净。但要认：**改一个通用 bug 要改两遍**。
2. **文档散在 8 处**（根 README、各层 README、columns.md、routes.json、记忆、技能），
   今天一次同步就找出 15 处过期。**这是当前最脆的地方** —— 已经加了「文档地图」防它。
3. **数字开头目录名**要 `sys.path.insert` 才导入，是绕过去的，不是设计。
4. **`routes.json` 零代码引用** —— 是死文档。留着当清单可以，别以为它在生效。
5. **「加工层不联网」这条铁律已经被打破** —— `cover.py` 会下图片。
   与其说是违规，不如说是**原定义太绝对**：真相是「出表和归档不联网，下载才联网」。
6. **旧脚本还堆在 `03_加工/01_lingzao/scripts/`**（5 个），是历史包袱，容易误抄。

### 没有的

**没有测试**。验证全靠手跑真数据 + 肉眼核对关键数字。
对这个规模（4260 行、两个源）够用，但**加第三个源时会更累**。

## 四、可迁移性

### 能整套搬走的（做同类项目直接抄）

| 模式 | 一句话 |
|---|---|
| **一个源一个文件夹 + 完全自包含** | 加新源 = 复制文件夹改三处（`config` / `ACTIONS` / `README`） |
| **四层分离**（采集 / 储存 / 加工 / 产出） | 每层只干一件事，层与层之间只靠"文件"通信 |
| **统一字段 + raw 兜底** | 出口统一成一套中文列名，入口原样留着 |
| **三态原则** | 有 / 0 / 未知 —— 数据源没有的不冒充 0 |
| **按 ID 认身份** | 名字会变、序号会错位，ID 不会 |
| **幂等归档** | 重跑不产生副本，才敢放心重跑 |
| **付费源预演** | 花钱的动作默认只打印不执行 |

### 不能搬的（跟源绑死）

字段映射、限流参数、封面时效处理、各源的"原文在哪个字段"。**这些正是要分开写代码的原因。**

### 迁移时会再踩的

数字开头的目录名、中文文件名的编码、`project_root` 往上两级的推断。

## 五、开发思路（这才是最该带走的东西）

### 主方法：**先摸清数据，再写代码**

每一步都按这个顺序，一次没跳过：

1. **先探后写** —— 每个数据源先真发一次请求、跑一次命令，看真实返回长什么样，再动适配器。
   **文档永远不全**：得到大脑 `blogger/contents` 文档写 5 个字段，实测返回 12 个。
2. **信实测不信文档** —— `note_type` 实测出现文档没列的 `class_audio`。
   写校验时**别拿文档枚举当白名单**，会漏数据。
3. **小样本先跑通** —— 20 条跑通了再谈全量。665 条 detail 要 58 分钟，这个数字是实测来的。
4. **分层验收** —— 每加一层，回头验上一层没被弄坏。
   改了共用的地基就拿旧数据回归一遍，**用证据代替保证**。
5. **坑当场写进技能** —— 踩一次的成本，换以后不再踩。
6. **架构让用户拍板** —— 冗余还是耦合，不是技术问题，是维护习惯问题。

### 三条最值钱的判断

**① 先问"这两个东西是一回事吗"，再动手。**
灵造和得到大脑的封面看着都是"封面"，实际一个 3 小时过期、一个永久有效。
**规则不一样就必须分开写**，硬合会互相带偏。

**② 静默错比报错危险。**
反引号被吃掉、字段名写错、CRLF 差异 —— 这三个都是"没报错但是错"。
**判据**：如果一段代码跑完没有输出、也没有报错，去确认它是真的没做事，还是做错了事。

**③ 别说"拿不到"，说"我还没走那条路"。**
我说过三次"拿不到"，三次都被纠正。
**"我的实现范围"和"客观限制"是两回事**，混起来说会让人以为路被堵死了。

### 一条反面的

**用"准备"替代"执行"。**
早期 40+ 次读文档、零产出、烧 12 元 —— 感觉在干活，其实没有可交付的东西。
**判据**：这一小时有没有一个能拿出来看的东西？没有，就是准备，不是干活。
