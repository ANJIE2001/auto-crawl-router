> 加第 3 个源（第 4、第 5 个也一样）时照这份做。
> 前两个源（灵造、得到大脑）已经踩过一遍，这份是把那遍的路固化下来。
>
> **三份文档怎么配合**：
> - **先测** → `新源测试流程.md`（这个平台值不值得接）
> - **再搭** → **就是这份**（按什么顺序搭）
> - **改完** → `目录说明.md`（哪几个文件夹、哪几处文档要跟着动）
>
> 动手前跑一下 `python 05_技能/selfcheck.py`。

## 0. 先问清三件事，再动手

| 问什么 | 为什么必须先问 |
|---|---|
| **花钱吗** | 花钱的源，动作默认只预演，加 `--go` 才真跑，而且**跑之前要跟用户报账**（余额 + 预计花费） |
| **给的是"内容"还是"数据"** | 只给内容的源，互动指标（点赞/收藏…）那几列全是「未知」——**别填 0** |
| **边界在哪** | 有的源账号里既有外部内容也有私人内容（如得到大脑），必须让用户划清哪些命令能用 |

**这三条没问清，后面全白做。**

## 1. 目录骨架：新源占三格

```
01_采集/0X_<源名>/     collect.py · config.json · config.local.json · README.md
02_储存/0X_<源名>/     （落盘目录，由 config 的 sub_dir 决定，自动建）
03_加工/0X_<源名>/     八个 .py（见第 3 节）
04_产出/               共用，不建源专属目录
```

**编号跟已有源顺延**（新源是 `03_xxx`，就写 `01_采集/03_xxx/`）。

**这一格必须自包含**：删掉这个文件夹，这个源就干净消失，不留断引用。
所以——**不引用别的源的任何文件**。宁可复制一份工具函数，也别抽公共模块。

## 2. 采集层：六个必须有

### ① `doctor` 自检
一条命令说清：工具在不在、连通吗、账号是谁、配置填对没有、哪些动作用得了。
**新人拿到这个文件夹，第一件事就是跑它。**

### ② `ACTIONS` 动作表
每个动作声明五样：**命令模板、参数、落盘命名、花不花钱、抓完接哪个加工动作**。

### ③ 付费动作默认只预演
不加 `--go` 就打印「要调什么命令、落到哪、花多少钱」然后停下。
**花费数字写进 `cost` 字段**，它会直接印在预演输出上——你控预算时盯的就是那一行。

### ④ `clean_after()`：抓完自动接清洗
用户原话：「**你抓到数据之后不会主动调用文件做清洗**」「只会抓到这些文件里，
没有产出的话，我是看不清也看不见的」。

所以每次真抓成功，**当次就把对应的加工跑掉**。做成**可选依赖**：
加工层被删了就跳过、采集照常工作。`--no-clean` 能关。

### ⑤ 凭证：进 git 的留空，真值单独放
```
config.json        进 git    结构 + 说明 + 申请地址，真值字段留空
config.local.json  不进 git  真值填这儿（.gitignore 里配好 01_采集/*/config.local.json）
```
**别把真值填进进 git 的那个文件。**

### ⑥ 落盘去重策略：先想清楚，别照抄隔壁
| | 覆盖 | 加序号留历史 |
|---|---|---|
| 什么时候用 | 不花钱、随时能重拉 | 重抓要花钱、数据每天在变 |
| 例 | 得到大脑 | 灵造 |

**选错了的后果**：文件名里带唯一 ID 的（像得到大脑的 `_blogger-content_<alias>`），
加序号会被下游当成**另一条**——实测把 20 条读成了 40 条。

### 模板：照隔壁源抄，别自己发明

**最省事的办法**：把 `01_采集/01_lingzao/` 整个复制成 `01_采集/03_xxx/`，
再逐块替换。两个现成的都行——想要「付费 + 留历史」抄灵造，想要「免费 + 覆盖」抄得到大脑。

`config.json` 的骨架就这几块（**具体字段名以隔壁源实际文件为准**）：

```jsonc
{
  "_这是给你的": "只用改下面几块，其余是给程序看的。填之前先跑 doctor。",
  "actions": {          // 动作 → 调什么命令、带什么参数、落哪个目录、花多少钱
    "xxx": {
      "label": "一句话说明这个动作干什么",
      "args": { "keyword": { "required": true, "help": "搜什么词" } },
      "store_dir": "02_储存/03_xxx/子目录名",
      "cost": "0 或 具体价格（会印在预跑输出上，预算就看这一行）",
      "clean_after": ["加工动作名"]      // 抓完自动接哪个加工命令，没有就省略
    }
  },
  "auth": {             // 凭证从哪来。真值不写这儿，写 config.local.json
    "where": "凭证文件的位置",
    "get_key_at": "去哪申请"
  },
  "examples": "给人看的命令行例子"
}
```

**`collect.py` 的 `ACTIONS` 表**跟上面 `actions` 一一对应，写四样：
`命令模板` / `参数` / `落盘命名` / `花不花钱`。

**`README.md` 的骨架**（照 `01_采集/02_getnote/README.md` 抄）：

```
这个源能抓什么 → 怎么配（新人第一步）→ 有哪些动作 → 花费 →
能调的接口清单 → ❌ 不能调什么（边界）→ 落盘长什么样 → 已知的坑
```

## 3. 加工层：八个文件的职责

| 文件 | 干什么 | 注意 |
|---|---|---|
| `util.py` | 纯工具：时间转换、取标签、路径展开、读 JSON | 不依赖同层的业务文件 |
| `record.py` | 定义统一字段 + 导出 csv/jsonl | **列名要和 `03_加工/columns.md` 对齐** |
| `adapter.py` | 源站的原始 JSON → 统一字段 | 认命令靠什么，写进注释 |
| `export.py` | 出 xlsx（版式 + 列宽） | 每个源一个底色，方便一眼区分 |
| `bundle.py` | 一条内容一个文件夹 + 封面归位 + 索引表 | 重跑要幂等 |
| `cover.py` | 封面下载（**这个源自己的规则**） | 见下 |
| `video.py` | 视频下载（拿不到直链就先做占位） | 占位也要把「现状 + 截图问用户」写好 |
| `run.py` | 命令行入口，把上面串起来 | 只做分派 |

**`adapter.py` 唯一的必答问题**：**认文件靠什么？** 两条路：
- 靠 JSON 里的 `data.type`（灵造是这样）
- 靠落盘文件名（得到大脑的 JSON 里压根没有 type 字段）

**改落盘命名之前，先回来看这份 adapter 靠什么认**——项目里认文件名的地方有**两处**
（`bundle.py` 的 glob + `adapter.py` 的正则），改名要同时过这两关。

### 封面：每个源的脾气都不一样，别套用

| | 带签名 | 有效期 | 所以怎么做 |
|---|---|---|---|
| 灵造 | 带（`t=` 时间戳） | **约 3 小时**，过了全 498 | **抓完当场抢**，晚了就废，救不回来 |
| 得到大脑 | 不带 | **永久** | 先取图池、没有就现下，链接随时可用 |

**新源先实测这一条**：URL 带不带签名、多久过期。判错了就是「该抢的没抢」或「白紧张」。

## 4. 字段对齐：`03_加工/columns.md` 的 30 列

**没数据的列填 `None`，导出成「未知」——绝不填 `0`。**

`0` 是「确实没互动」，`未知` 是「这个来源压根没这个字段」。混在一起会让人误判。

加列/改列名/删列都在 `columns.md` 末尾有规矩，照那个走。

---

## 5. 命名与落盘：六条硬规矩

1. **博主目录 = `昵称_账号ID`** —— 改昵称了也能对回账号
2. **单条目录 = `发布日期_标题`，不用 `001` 序号** —— 增量抓时序号会错位
3. **单条目录里的文件名固定**（`逐字稿.md` / `封面.*`）—— 固定了才能一个脚本跑全部博主
4. **身份永远认唯一 ID**，文件夹名只是给人看的
5. **标题清洗只清半角 `\/:*?"<>|`** —— 全角 `？！：` 是合法字符，别误伤；超 40 字截断
6. **标题一个字都不许改**（用户定死的铁律）—— 源站给的 AI 标题永远不能覆盖原帖标题

**原始数据层要留"来源记录"**：下了什么、从哪个 URL、校验过没有、落地叫什么名。
写成跟主文件**同前缀**的小文件（如 `<主文件名>_artifacts.json`），
别指望以后去几百 KB 的 JSON 里 grep URL。
服务端给了 `sha256` 就用上——**只比 size 不够，内容坏掉不一定改大小**。

## 6. 端到端验收清单

> **还没接的新平台**：先走 `新源测试流程.md`（L0–L3 + 判定表），
> 测出「值得接」再动手搭。搭完用下面这张清单收尾。

搭完**逐条打勾**，缺一条都算没做完：

- [ ] `collect.py doctor` 全绿
- [ ] 付费动作不加 `--go` 只预演，花费数字正确
- [ ] 真抓一次，原始数据落进 `02_储存/0X_<源名>/`
- [ ] **`04_产出/` 里出东西了**（抓完自动接清洗生效）
- [ ] 重跑一次，**幂等**（不堆 `_2` 目录、条数不变）
- [ ] 表格列名和 `columns.md` 对得上
- [ ] 没有数据的列显示「未知」而不是 0
- [ ] 封面：图的张数对得上，缺的能说清原因
- [ ] 删掉 `03_加工/0X_<源名>/` 整个文件夹 → 采集照常工作，只提示一句
- [ ] `README.md` 写清：这个源能抓什么、怎么配、边界在哪

## 7. 别做的事

- **别把两个源合进一个文件夹。** 用户拍板过：宁可冗余，也不要混在一起
  ——「因为真的很难去检查和维护」。
- **别抽公共父类 / 公共引擎。** 同上，允许重复。
- **别的源的数据别往这个源里塞。** 各源各自落盘，产出层才汇合。
- **别照抄文档的字段表。** 实测回来的字段**常常比文档多**（得到大脑的博主内容：
  文档写 5 个、实测 12 个）。写适配器前先把真实响应 dump 出来看。
- **别拿文档的枚举当白名单校验。** 实测出现过 `class_audio` 这种文档里没有的取值。
