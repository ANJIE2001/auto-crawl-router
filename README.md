# 自动抓取内容路由

把散在灵造、得到大脑里的**外部内容**抓回来，落成统一字段，再产出表格。

一件事：**内容进来 → 存下来 → 洗干净 → 出成品。**

> 👉 **只想看「怎么用、怎么维护」？看 [使用说明.md](使用说明.md)。**
> 这份 README 偏开发和维护，技术细节更多。

---

## 五层骨架

| 层 | 干什么 | 在哪 |
|---|---|---|
| `00_路由` | 来源清单（**手写备查，目前没有代码在读它**） | `routes.json` |
| `01_采集` | 抓回来，**原样**落盘 | `01_采集/<源>/collect.py` |
| `02_储存` | 原始数据，只进不改 | 按来源分文件夹 |
| `03_加工` | 统一字段、清洗、转表格、下载封面 | `03_加工/<源>/` |
| `04_产出` | 给人看的东西 | `博主/` `图片/` `表格/` |
| `05_技能` | **规范 / 复盘 / 手册**（不装代码） | `05_技能/` |

数据流向单线：`采集 → 储存（原始） → 加工 → 产出`。**不回头改写原始数据。**

`05_技能` 不在流水线上——它讲的是**这条流水线该怎么搭、怎么改**。

| 想干什么 | 读哪份 |
|---|---|
| **第一次用，或者换了台电脑** | `python 05_技能/prereq_check.py` —— 装了没、凭证配了没 |
| 找不着北：哪个文件夹干什么、改完要同步哪儿 | `05_技能/目录说明.md` |
| **要试一个新平台** | `05_技能/新源测试流程.md` |
| **要加第 3 个源** | `05_技能/新增渠道规范.md` |
| **要打包发给别人** | `05_技能/打包排除清单.md` |
| 想知道当初为什么这么定 | `05_技能/开发复盘.md` |
| 动手前 | `python 05_技能/selfcheck.py` |

## 一个源一个文件夹

**三层完全对称**，一个源一条线，互不牵连：

```
01_采集/                  02_储存/                03_加工/
├── 01_lingzao/    ←→     ├── 01_lingzao/  ←→    ├── 01_lingzao/
└── 02_getnote/    ←→     └── 02_getnote/  ←→    └── 02_getnote/
```

| 源 | 干什么 | 花钱吗 |
|---|---|---|
| `01_lingzao` | 主动去搜：按关键词搜笔记、深挖单个博主 | 花。搜一次 20 积分；博主深度解析按条数 **50 / 100** 分档 |
| `02_getnote` | 读**外部内容**：订阅博主的逐字稿 + 封面 | 不花（会员制，只占次数） |

每个源文件夹都是**自包含**的——拷到哪儿都能跑，删掉就是卸载，不影响另一个。
代价是代码允许重复；详见 `01_采集/README.md` 和 `03_加工/columns.md`。

⚠️ **得到大脑只用「外抓」命令，不碰私人笔记。** 边界写在 `01_采集/02_getnote/README.md`。

## 快速开始

```bash
# 第 0 步：查环境 —— 灵造装了没、得到大脑的 key 配了没。缺什么它会说怎么装
python 05_技能/prereq_check.py

# 第 0.5 步：配凭证（key 存你自己电脑，项目里不留）
python 05_技能/set_key.py getnote --client-id cli_xxx --api-key gk_live_xxx

# 采集层不用装任何东西（只用 Python 标准库）；加工层要 openpyxl
pip install openpyxl

# 1. 灵造（花钱，不加 --go 只预演、不花钱）
python 01_采集/01_lingzao/collect.py doctor
python 01_采集/01_lingzao/collect.py search --keyword "AI写作"
python 01_采集/01_lingzao/collect.py search --keyword "AI写作" --go

# 2. 得到大脑：一条命令抓详情 + 自动出表（全走 HTTP，不花钱）
python 01_采集/02_getnote/collect.py bloggers --topic <topic_id>     # 拿 follow_id
python 01_采集/02_getnote/collect.py details  --topic <topic_id> --follow <follow_id>

# 3. 加工（每个源一个入口。采集已经自动接过一次，这里是单独重跑用）
python 03_加工/01_lingzao/run.py  bundle "02_储存/01_lingzao/analyze-user-profile/<文件>.json"
python 03_加工/02_getnote/run.py blogger "02_储存/02_getnote/blogger"

# 4. 补封面（两个源规则不同，各走各的；得到大脑通常不用补）
python 03_加工/01_lingzao/run.py  cover "02_储存/01_lingzao/analyze-user-profile/"
python 03_加工/02_getnote/run.py cover "02_储存/02_getnote/blogger"
```

命令全表：`python 03_加工/<源>/run.py --help`

## 路由规则（一句话版）

- 搜公开内容、深挖博主 → **灵造**（花钱，字段全，小红书）
- 看订阅博主的逐字稿、拿封面 → **得到大脑**（不花钱，抖音）
- 两个都不可用时才有浏览器兜底（尚未实现）

`00_路由/routes.json` 是这份清单的详细版，**目前没有代码在读它**，当文档用。

## 坑（别踩）

- **`02_储存` 和 `04_产出` 不入 git**。体积大，`.gitignore` 已排除；换机器要手动拷。
  好在这两个目录的**结构由代码自动创建**，clone 下来照样跑。
- **灵造花钱的动作默认不执行**。不加 `--go` 只预演：打印命令、落盘路径、花费，然后停下。
- **灵造积分花得快**。搜索一次 20，博主深度解析 1–20 条 **50** / 21–40 条 **100**。
  **动手前先跟用户报账**（余额和预计花费）。
- **灵造 profile JSON 里的字幕是截断的**（实测卡 1203 字）。全文在**响应顶层**
  `data.artifacts.subtitle_markdown.url` —— **不在 `items[].artifacts`**，那个是空的。
  采集时已自动下成 `<JSON名>_完整字幕合集.md`，旁边还有一份 `<JSON名>_artifacts.json`
  记着 URL、sha256 和下载结果 —— **想重下全文就查那份小文件**，别去 grep 几百 KB 的 JSON。
- **灵造的封面 URL 只有约 3 小时寿命**（带 `t=` 签名），过了全 498，**抢救不回来** ——
  想拿新链接只能重抓（花钱）。采集时已自动抢一遍，漏了用 `run.py cover` 趁窗口补。
- **得到大脑的封面链接不过期**（不带签名）。采集时 HTTP 详情接口一并给 `post_cover`，
  落进本地 JSON；加工归档时**先取图池、图池没有就用它现下** —— 所以封面不会缺。
  想把图池一次性补满：`python 03_加工/02_getnote/run.py cover`。
- **得到大脑的标题不能被 AI 改**。用 `save` 存链接时必须自己传 `--title`。
- **★ 凭证只存你自己的电脑，项目里一个 key 都不留**。灵造归 CLI 管
  （`~/.lingzao/config.json`，不用你操心）；得到大脑存成**用户环境变量**
  （底层就是注册表 `HKCU\Environment`）—— 这样**打包发人，包里也没有钥匙**。
  设凭证：`python 05_技能/set_key.py getnote --client-id cli_xxx --api-key gk_live_xxx`
  看当前存在哪：`python 05_技能/set_key.py`（不加参数就是查看）。
  打包前照 `05_技能/打包排除清单.md` 再对一遍。
- **别在 Git Bash 里直接敲 `getnote`**。Git Bash 会命中 npm 生成的那个无扩展名 sh 脚本然后崩；
  用 CMD / PowerShell，或者干脆走 `collect.py`（它只认 `.cmd` / `.exe`）。

## 统一字段

加工层所有来源都吐**同一套中文列名**（30 列），见 `03_加工/columns.md`。

各源各自实现自己的字段定义（`03_加工/<源>/record.py`），**代码分开、列名统一** ——
这样删一个源不影响另一个，两张表又能在 Excel 里对齐。

要点两条：

1. **统一字段之外，原始条目整条挂在 `raw` 上**。清洗出错时能对回原样。
2. **「未知」不是 0**。得到大脑没有互动数据（点赞/收藏/评论/分享）和时长，
   那几列导出成「未知」—— 别拿它去加总，会得出错的结论。
